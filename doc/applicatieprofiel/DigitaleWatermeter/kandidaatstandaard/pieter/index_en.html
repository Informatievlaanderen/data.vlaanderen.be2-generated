This document describes an application profile, in this case Digital Water Meter Application Profile. The application profile specifies a semantic data model covering a set of usecases. The specification consists of terms with their constraints (cardinalities, codelists, usage guidelines).

Summary

The application profile "Digital Water Meter" describes how water consumption in Flanders is monitored using digital meters. These meters are equipped with sensors that record water consumption and provide information about, among other things, the type, manufacturer, and status of the meter. The consumption data, consisting of observations of water usage, provide insight into individual and aggregated consumption, as well as in predicted consumption patterns. This profile provides a framework for collecting and sharing this data with third parties.

ISO19156:2011 is reused to align as much as possible with existing OSLO data standards, even if those URLs no longer resolve. To look up the definitions of those URLs, you can go on https://data.vlaanderen.be/doc/applicatieprofiel/sensoren-en-bemonstering/ . . .

Observation

Description
Determining the value of a particular attribute of an Object at a specific point in time or between two points in time.
Usage
These are estimates of the value, meaning there is a certain margin of error on the value. Examples are temperature, class, color. This is different from values that have been assigned and are therefore not estimates such as name or price.
Properties
For this entity the following properties are defined: AssociateObservation , executed By , executedWithSensor , identifier , observedObject , parameter , phenomenon , phenomenon time , Procedure used , result , result quality , result time , type , validTime .
Property Expected Range Cardinality Description Usage Codelist
AssociateObservation Observation 0..* Observations whose results are somehow related. It concerns coherence that is important to understand the outcome of individual Observations, for example biotic relationships (animal A is a predator and is present because animal B is prey). Such relationships require to be explicitly described (as opposed to relationships such as the coincidence of Observation results in space or time, which may remain implicit). Also useful for relationships where the output of Observation A forms the input for Observation B.
executed By agent 0..* Agent who performed the Observation.
executedWithSensor Sensor 1 Sensor used to perform the Observation.
identifier identifier 0..* The person or thing that serves to establish the observation.
observedObject Domain object 1 EVERYTHING.
parameter Denominated Value 0..* Random data associated with the occurrence of the Observation. This is not about characteristics of the observed object (which are already described by the observed attribute) or parameters associated with the observation process (such as an instrument setting). For example, it concerns environmental parameters that can influence the result and are important for interpreting the result correctly. An example is the depth in a water well where water quality was measured or the ambient temperature when measuring humidity.
phenomenon Feature type 1 EVERYTHING. EVERYTHING.
phenomenon time temporal entity 1 The moment at which the result of the Observation was applicable. Typically, the moment when observation or sampling took place. If the Observation is temporal and the moment when something happens is recorded, then this is immediately also the phenomenon time.
Procedure used Observation procedure 0..* The observation procedure used.
result Any 1 Result of the observation. The result can be of any type since any attribute of any type of object can be observed. CONSTRAINT: The type of the Observation result must match the observed attribute and the obtained value must fall within the range of the observed attribute.
result quality Quality element 0..* Extent to which the result of the Observation meets the requirements or expectations. These are data that are specific to the Observation and complementary to the description of the procedure followed during the Observation (analysis method and the like, see class Process), which in itself says something about the quality of the result.
result time moment 1 Time at which the result of the Observation was obtained. For some Observations, it is equal to the phenomenon time but can also differ, for example when performing an analysis on a Sample that was taken earlier (and usually then and so on) or in sensor measurements that are processed later. Also useful to distinguish repeated Observations, for example on the same Sample. If the result is a prediction, then the phenomenon time is the moment at which it should apply.
type Observation type 0..* The type of observation.
validTime Period 0..1 Period for which the result of the Observation applies. For example, useful for weather forecasts.

administrativeUnitLevel2 LangString 0..1 The region of address, usually a province or state or similar area that typically includes several places.
