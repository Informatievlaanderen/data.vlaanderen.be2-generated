MAGDA Service Desk

This document describes an implementation model, in this case Implementation model MAGDA-Persoon. This implementation model answers the question of how the corresponding domain model can be applied in practice. It explains the constraints (cardinality, code lists) and lists the corresponding (RDF) terms.

Summary

The MAGDA-Person Implementation Model is based on the OSLO Person Application Profile to encompass the MAGDA person services according to this OSLO data standard.

The personal services allow the customer to retrieve the current data of a person, based on the INSZ number of this person. Once the customer has launched the request, the request is forwarded to the National Register or the Crossroads Bank for Social Security (CBSS). This depends on the permissions of the customer and the choice of source in the question.

Belgian Address

Description
Information that allows a structured and unique way to refer to a building unit, a berth, a stand or a plot based on a municipality name, a street name, a house number and possibly a bus number and a postal code.
Usage
The definition refers to Belgian addresses. In other countries, an address may refer to other geographical objects (not a building unit or plot) or consist of other designations (different from house number and box number) or of components other than street name, municipality name or postal code. Alternative address designations other than house number or bus number (for example: entrance indication, staircase indication, floor indication, etc.) or a building name or room name, etc., are possible by means of an association with address extension. Exchange of foreign addresses must be done using the Address Representation object.

Registered Person

Description
Person whose data is registered in a register.
Usage
This register is usually a population register, but it can also be an electoral register, for example. The registered data relate to the identity (example: surname and first name) and the place of residence of the person and to important life events such as birth, marriage, death, etc. These data are typically recorded by the government, they provide legal protection to the registered person and allow the government to compile basic statistics on its population.
Subclass of
Person

Property Expected Type Cardinality Description Usage Codelist
admin AdministrativeAdministrator 0..* Reference to the Administrator of the person's file. Normally there is only 1 administrator present with a person, but in exceptional cases there may be several administrators. For example: the person has an address abroad, is moving between municipalities, etc.
File status Dossier status 0..1 Status of the Registry file. Used in the National Register when the registration in the register is no longer valid, for example: because the person has been removed from the register or a previous registration was cancelled or the person has died, etc. Link
previousRegistration Identifier 0..1 The reference file of the person who contains the previous registration. Only applicable if a reference file exists according to IT002.
reasonAbsence ReasonAbsence 0..1 Reason why the Person is absent. Link

Description
More readable presentation with only the basic data of the address, intended for the use of an address as an attribute of another object.
Usage
For example, as an attribute of a person or building, ... The Address Presentation does not only relate to Belgian addresses, it can be used to represent foreign addresses (where possible address indications other than house number or box number are used or where address components such as address areas occur).
Subclass of
Location
Properties

Box , Post Name , Postal code , redirectsTo , street name .
Property Expected Type Cardinality Description Usage Codelist
Address area LangString 0..1 Name of a geographical area or place that groups a number of addressable objects to address them without the area or place being an administrative unit. For example: the name of the hamlet in which the address is located.
administrativeUnitLevel1 LangString 0..1 Highest Administrative Unit of the address, usually a country.
administrativeUnitLevel2 LangString 0..1 The region of the address, usually a province or state or similar area that typically includes several places.
Box number String 0..1 Officially assigned alphanumeric code that is added to the house number to distinguish several building units, pitches, berths or plots that have the same house number. Specialization of Address Presentation: location indication for Belgian addresses.
completeAddress LangString 0..1 The complete address in one string, formatted or not. Avoids errors due to splitting an address into its parts. Displays the prescribed order of the different parts.
Country LangString 0..1 Country in which the address is located.
House number String 0..1 Alphanumeric code officially assigned to building units, berths, stands or plots. Specialization of Address Presentation: location indication for Belgian addresses.
Location Indicator String 0..* Alphanumeric code that uniquely identifies the address locator within the street, administrative unit etc.
Location name LangString 0..* Name or description of the geographical object that the address locator denotes.

P.O. Box String 0..1 PO Box number in a post office.

Postal code String 0..1 Code that identifies the geographical area that groups addresses for postal purposes.
